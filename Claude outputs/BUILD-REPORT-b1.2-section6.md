## 4. Known gaps and the authoring TODO

1. **Reading sits at ~2% against a 5% target in both sections.** This is honest
   rather than fixable by generating more items: at A1 there is very little text
   long enough to read. The fix is graded readers in the Immersion Engine
   (docs/06 §7), not more exercises.
2. **Grammar items are ~4 points below target.** Each grammar point now has
   exactly one home node, which is correct; the shortfall should be closed with
   hand-authored contrast items rather than more generated variants.
3. **Item volume runs at roughly 60-70% of the modelled lesson time.** Each
   node-tier averages ~13 items where ~16-18 are needed. The remainder should be
   hand-authored variety, not more of the same templates.
4. **All audio is referenced but not recorded.** Human voices are required below
   C1 (docs/15 §5).
5. **No images yet.** `mcq_image` and `listen_choose_image` are unused for that
   reason; at A1 they matter, and image sourcing is the next media task.
6. **B1 is now content-complete.** Section 6 added 32 grammar points
   (G-175…G-206), 8 phonology points (P-053…P-060), 18 functions
   (F-077…F-094), 16 story episodes and 48 comprehension questions. Like
   Section 5, its syllabus had to be authored from scratch. G-175 closes the
   reflexive-pronoun omission logged against Section 5.
7. **Section 6 ships 627 lexemes, not the 800 docs/13 §3.1 asks for, and the
   800 is the number that is wrong.** After 2,620 taught lexemes covering
   A1-B1.1, genuinely new B1.2 vocabulary is close to exhausted. Reaching 800
   meant three kinds of padding and nothing else: inflections of words already
   taught (84 candidates, now blocked by G23), C1 vocabulary moved down a level
   (~111), and four-member derivational clusters where two members earn their
   place (~37). A flat 800 per section is a planning assumption that does not
   survive contact with the lexicon; docs/13 should taper B1.2 and rise again
   at B2, where technical and academic vocabulary reopens.
8. **Twenty-two everyday words were missing from the course entirely.**
   Section 6's stories were the first content to reach for `paper`, `page`,
   `full`, `wrong`, `language`, `follow`, `quick`, `outside`, `everyone`,
   `else`, `at least`, `even`, `argue`, `expect`, `thank`, `mind`, `correct`
   and `owner` — none of which any unit taught — while `man`, `woman`, `twice`
   and `date` had drifted as far as Section 6. All are now taught where a
   learner first needs them (`content/lexemes/src-gap-topup.json`), which is
   Sections 1-3, not Section 6.
9. **`owner` hid for five sections because the builder invented it.** The
   adjective rule generated -er/-est by word length, so `own` produced `owner`,
   `careful` produced `carefuler` and `crowded` produced `crowdedder`. Those
   non-words entered `available_forms`, so the vocabulary gate accepted any
   content using them. The rule is now syllabic, which is the real English one:
   one syllable always; two only for -y, consonant+-le and -ow; participles and
   non-gradable adjectives never. That removed ~150 invented forms and
   immediately exposed `owner` as untaught.
10. **193 band-1000 lexemes are still first taught at B1 or later** — gate G24.
   This is the same defect class as item 8, seen from the corpus rather than
   from the content, and it is a real backlog: `part`, `life`, `question`,
   `example`, `point`, `voice`, `several`, `rather`, `although` and `however`
   are all B1-or-later in a course that teaches them nowhere earlier. G24 warns
   rather than blocks, because the bands are authored estimates and a third of
   the list (`analysis`, `election`, `significant`) is common in print but
   genuinely B1 in a classroom. Fixing it means re-opening Sections 1-4.
11. **Section 7 (B2.1, units 85-102) is next** — 18 units, and the first
   section where the lexicon should widen again. The pipeline needs no changes;
   the B2 syllabus does have to be authored from scratch.

## 5. How to rebuild

```
./build.sh
```

which runs, in order:

```
python3 tools/build_lexemes.py   # compact sources  -> build/lexemes.json
python3 tools/build_units.py     # unit specs       -> build/units/*.json
python3 tools/build_items.py     # everything above -> build/items/*.json
python3 tools/validate.py        # the CI gates (exit 1 blocks a merge)
python3 tools/report.py          # this file
```

Builds are deterministic (`random.seed(20260908)`), so the same sources always
produce the same item ids.
